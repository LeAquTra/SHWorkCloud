## 0. 通用约定

### 0.1 路径与鉴权

- 对外完整路径 = `context-path(/api)` + Controller 映射，例如 `/api/auth/login`；
- 除公开接口外，请求头必须带 `Authorization: <token>`（原始 token，**不加 Bearer 前缀**）；
- 公开接口：`/api/auth/login`、`/api/auth/register-config`、`/api/auth/captcha`、
  `/api/auth/captcha/verify`、`/api/auth/email-code`、`/api/auth/register`。

### 0.2 统一返回

```json
{ "code": 0, "message": "ok", "data": { } }
```

- **业务错误一律 HTTP 200**，靠 `code` 判断；
- 只有两种例外：未登录 → **HTTP 401**（code 40100）、无权限 → **HTTP 403**（code 40300）。

### 0.3 关键错误码

| code | 含义 | 处理建议 |
|------|------|----------|
| 0 | 成功 | — |
| 40000 | 参数错误 | 看 message |
| 40004 | 接口不存在 | 前端地址拼错、或前后端版本不一致（**不是**服务端崩溃） |
| 40005 | 请求方法不支持 | message 里会写明该用 GET 还是 POST（例如 `/auth/captcha` 只支持 GET） |
| 40006 | 请求 Content-Type 不支持 | 该传 JSON 的接口要带 `Content-Type: application/json` |
| 40010 | 存储空间不足 | 提示清理回收站 |
| 40020 | 同级同名文件 | 服务端一般会自动加 `(1)`，很少直接返回 |
| 40061 | 上传凭证无效/已过期 | 重新申请 `/oss/ticket` |
| 40070 | 文件不存在或无权访问 | 越权与不存在统一返回，避免探测 |
| 40100 | 未登录/会话失效 | 重新登录 |
| 40104 | 验证码题库为空 | 管理员需先上传题目（仅图片验证码开启时相关） |
| 40105 | 需要人机验证（未带 / 无效凭证） | 见 §0.8：弹验证码窗口 → 拿 `captchaPassToken` → 重试；上传场景见免验证窗口 |
| 40103 | 验证凭证无效或已被使用 | 与 40105 一样处理：重新过一次验证码 |
| 40113 / 40114 | 发送过于频繁 / 超限 | 等待或换账号 |
| 40116 | 账号或密码错误 | — |
| 40117 | 账号已禁用 | 联系老师 |
| 40118 | 账号已锁定 | 默认连错 5 次锁 10 分钟 |
| 40119 | 需先修改初始密码 | 调 `POST /auth/password` |
| 40121 | 学号已存在 | 名单导入时 |
| 40122 | 自助注册未开放 | 把 `app.register.enabled` 设为 true |
| 40123 | 头像修改过于频繁 | 每 24 小时只能改一次，`message` 里带下次可改时间 |
| 40094 | 公告不存在 | 多半是已被删除，刷新列表 |
| 40095 | 公告当前状态不允许该操作 | 已发布的公告要先撤回才能改/删 |
| 40300 | 无权限 | 角色不足 |
| 50010 / 50020 / 50030 | OSS / 邮件 / STS 异常 | 看服务端日志 |

### 0.4 viewType：文件该怎么渲染（前端必读）

列表接口会为每个文件下发 `viewType`，**前端不必自己维护一份后缀白名单**（两边各写一份迟早不一致）。

| viewType | 典型后缀 | 渲染方式 | 用哪个接口 | 需要 Authorization？ |
|----------|----------|----------|-----------|:---:|
| `image` | jpg / jpeg / png / gif / webp / bmp | `<img>` / `el-image` | `preview-url`（签名，首选）或 `GET /files/{id}/preview` | 签名地址：否；流式接口：是 |
| `pdf` | pdf | ⚠️ **不支持在线预览**（需求方明确要求） | 只能 `download-url` / `GET /files/{id}/download` | — |
| `video` | mp4 / webm / mov … | `<video>` | 同上（支持 Range，可拖进度条） | 同上 |
| `audio` | mp3 / wav / m4a … | `<audio>` | 同上（支持 Range） | 同上 |
| `text` | txt / md / csv / json / 日志 / 源码 | 代码或文本查看器 | `GET /files/{id}/text` | 是 |
| `office` | doc / docx / pptx / xlsx | **结构化 HTML**（`TextContentVo.html`），排版近似但非像素级；回退纯文本 | `GET /files/{id}/text` | 是 |
| `none` | zip / exe / ppt / xls… | 只能下载 | `download-url` 或 `download` | — |

**关于 `pdf`**：`viewType` 仍然是 `pdf`（分类筛选、文件图标还要用它），
但 `previewable` 为 **false**，`GET /files/{id}/preview-url` 会返回 `40073`。
前端应当**点击整行不弹窗、操作下拉框里不出现"在线预览"**，只保留下载入口 ——
所以判断能不能预览请一律用 `previewable`，不要用 `viewType !== 'none'`。

**安全边界（后端已处理，前端不用管）**：`html` / `svg` / `js` 这些虽然能"阅览"（走 `text` 通道返回纯文本），
但**永远不会被内联渲染** —— 后端内联响应头里的 `Content-Type` 来自白名单映射，
不会回显上传者声明的类型，并带 `X-Content-Type-Options: nosniff`。

### 0.5 鉴权与 `<img>` / `<video>` 的硬限制（最容易踩的坑）

`Authorization` 只能通过请求头传。而浏览器的 **`<img>` / `<video>` / `<audio>` / `<iframe>` / `<a download>`
标签无法携带自定义请求头**。所以：

| 方案 | 做法 | 评价 |
|------|------|------|
| ① 用后端给的签名地址 | 直接 `src="avatarUrl"` / `preview-url` 的返回值 | ✅ **首选**：简单、不占业务服务器带宽，且签名地址自带有效期 |
| ② fetch 后转 blob URL | `fetch(url, { headers })` → `URL.createObjectURL(blob)` → 赋给 `src` | ✅ 需要带请求头时用；记得组件卸载时 `URL.revokeObjectURL` 释放内存 |
| ③ 把 token 放 URL 查询参数 | `?token=xxx` | ❌ **不要**：token 会进 Nginx/浏览器日志与 Referer |

签名地址的有效期：头像 1 小时、下载 10 分钟、相册预览 1 小时。过期后重新调对应接口刷新即可。

**Token 存放**：请存 **`sessionStorage`** 而不是 `localStorage`。
机房是共用电脑，`localStorage` 会让下一位同学打开浏览器就进上一位的网盘。同时请做**空闲自动登出**。

**错误码 → 页面动作**：

| code | 前端应该做 |
|------|------------|
| `40100` | 清登录态 → 跳登录页 |
| `40117` | 清登录态 → 提示"账号已被禁用，请联系老师" |
| `40119` | 跳"修改密码"页（首登强制改密） |
| `40010` | 提示空间不足 + 给"清空回收站"入口（回收站占用在 `GET /user/quota` 的 `recycleUsed`） |
| `40082` | 单个文件超限；头像/文本阅览超限也是它 |
| `40061` | 上传凭证过期 → 重新走一遍 `ticket` |
| `40104` | 验证码题库为空（仅当开启了图片验证码）→ 提示联系管理员 |
| `40105` / `40103` | 需要（重新）完成人机验证 → 弹验证码窗口，拿到凭证后重试一次（见 §0.8） |
| `40123` | 头像冷却中 → 按钮置灰 + 显示"还剩多久"，不要只弹一个 toast |
| `40094` / `40095` | 公告不存在 / 状态不允许 → 刷新列表，提示"先撤回再修改" |
| `40300` | 跳 403 页（不要只弹 toast） |

### 0.6 页面 → 接口映射（照着接就行）

| 页面 | 需要的接口 |
|------|-----------|
| 登录页 | `GET /auth/register-config`（决定要不要显示注册入口）、`GET /auth/human-check`（决定点登录要不要先弹验证码）、`POST /auth/login` |
| 注册弹窗（可选） | `GET /auth/captcha` → `POST /auth/captcha/verify` → `POST /auth/email-code` → `POST /auth/register`<br>要不要走前两步看 `human-check.register`（见 §0.8） |
| 强制改密页 | `POST /auth/password` |
| 文件列表页 | `GET /user/profile`（容量+身份）、`GET /files`、`GET /files/tree`、`GET /files/breadcrumb`、`POST /folders`、`PUT /files/rename`、`POST /files/move`、`DELETE /files`、`GET /files/{id}/download-url` |
| 图片管理页 | `GET /images`（已带签名 `previewUrl`，可直接铺网格） |
| 上传面板 | `GET /user/quota` → `POST /oss/ticket`（可能需先过人机验证）→ `POST /oss/put-url` 或 `POST /oss/multipart/init` + `/multipart/part-urls` → `POST /files/commit`；上传上限见 `GET /oss/upload-config` |
| 在线阅览弹窗 | 按 `previewable` / `viewType` 分流：`GET /files/{id}/preview-url`（image/video/audio）或 `GET /files/{id}/text`（text/office）；**pdf 不可预览** |
| 回收站 | `GET /recycle`、`POST /recycle/restore`、`DELETE /recycle/purge`、`DELETE /recycle/empty` |
| 个人信息页 | `GET /user/profile`、`PUT /user/profile`、`POST /user/avatar`、`DELETE /user/avatar`、`GET /user/quota`；头像有 24 小时冷却（看 `avatarChangeableAt`） |
| 公告（全站） | `GET /announcements/active`：1/2 级顶部横幅（可关）、3 级强制弹窗 |
| 公告管理（超管） | 见 §8：列表 / 新建 / 修改 / 发布 / 撤回 / 删除 |
| 管理后台 | 见 §7；顶部导航按 `role` 显示（`2` 教师 / `1` 管理员 / `9` 超管） |

### 0.7 分页与列表约定

- `page` **从 1 开始**；`size` 默认 50（文件）／20（后台）／60（相册），服务端上限 200；
- 返回统一为 `{ page, size, total, records }`；
- 文件列表排序固定为**文件夹在前、然后按名称升序**；相册按上传时间倒序；
- `keyword` 是**前缀匹配**（`LIKE 'x%'`），不是模糊包含 —— 界面提示文案请写"输入开头几个字"；
- `category` 取值：`image` / `document` / `video` / `audio` / `other`（只筛当前目录的文件，文件夹始终显示）。

### 0.8 人机验证（登录 / 注册 / 上传三处）

后台维护的**图片验证码题库**在三个动作前做人工验证。前端**不要自己猜**要不要弹窗，
先问服务端：

```bash
curl http://localhost:8081/api/auth/human-check      # 公开接口
```

```json
{ "code": 0, "message": "ok",
  "data": { "login": true, "register": true, "upload": true, "passTtlSeconds": 300 } }
```

| 字段 | 含义 |
|------|------|
| `login` | 点登录时要先过人机验证 |
| `register` | 注册「发送邮箱验证码」之前要过人机验证 |
| `upload` | 申请上传凭证（上传文件）之前要过人机验证 |
| `passTtlSeconds` | 通过验证后凭证 `captchaPassToken` 的有效秒数 |

⚠️ **这三个值是"生效值"，不只是配置值**：后台题库为空（全新部署、题目被删光）时
服务端会自动降级为 `false`。这是刻意的护栏 —— 登录是机房的主路径，
绝不能被一个人为可空的条件挡死（判定逻辑见 `CaptchaRules.required`）。

**标准对接流程**（三个场景完全一样）：

```
① 动作之前看 human-check 对应的开关
     true  → 弹验证码窗口：GET /auth/captcha 出题 → POST /auth/captcha/verify 作答
             → 拿到 captchaPassToken
     false → 跳过
② 带着 captchaPassToken 调真正的接口（login / email-code / oss/ticket）
③ 若仍返回 40105（或 40103），说明配置在页面停留期间变了：
   强制弹一次窗口，拿到新凭证后**重试一次**即可
```

各接口的凭证传递方式：

| 场景 | 接口 | 凭证怎么传 |
|------|------|-----------|
| 登录 | `POST /auth/login` | 请求体 `captchaPassToken` |
| 注册 | `POST /auth/email-code` | 请求体 `captchaPassToken`（**一次性**：每次发码都要重新验证） |
| 上传 | `POST /oss/ticket`、`GET /oss/sts` | 请求体 / 查询参数 `captchaPassToken` |

**上传的免验证窗口**：整文件夹上传可能有几十个文件，每个都过一次验证码是不可用的设计。
通过一次后服务端为该用户开启 **`app.captcha.upload-pass-minutes`（默认 10 分钟）** 的窗口，
窗口内申请凭证不再要求验证码。

**凭证的消费规则**（前端只需知道结论）：

| 场景 | 是否一次性 | 原因 |
|------|:---:|------|
| 登录 | ❌ 不消费（5 分钟内可重复用） | 密码输错重试时不该逼用户重做一次验证码 |
| 上传 | ❌ 不消费（由免验证窗口接管） | 并发申请多个凭证时，若谁先到谁消费，其余就会失败 |
| 注册发码 | ✅ **一次性消费** | 否则同一个凭证能被反复用来刷邮件验证码 |

**临时关闭**：`app.captcha.enabled=false`（或按场景关 `require-on-login` /
`require-on-register` / `require-on-upload`）会让验证码立刻失效，
用于题库被误删等紧急场景，**不必重新打包**。

## 1. 自助注册（本次新增/开启）

### 1.1 先问服务端要哪一种流程

```bash
curl http://localhost:8081/api/auth/register-config
```

```json
{
  "code": 0, "message": "ok",
  "data": {
    "registerEnabled": true,
    "requireImageCaptcha": true,
    "mailEnabled": true,
    "emailPattern": "^\\d{5,11}@qq\\.com$",
    "mailHint": "需先获取邮箱验证码，再提交注册"
  }
}
```

`requireImageCaptcha` 决定"发送邮箱验证码"之前要不要多走一步图片验证码。
⚠️ 它是**生效值**：配置开着但题库为空时会是 `false`（否则谁都注册不了）。
线上一般直接看 `GET /auth/human-check` 的 `register` 字段（见 §0.8）。

| 取值 | 流程 | 适用 |
|------|------|------|
| `false` | 邮箱验证码 → 注册 | 题库为空、或运维临时关掉了人机验证 |
| `true` | 图片验证码 → 邮箱验证码 → 注册 | 题库已维护好（有题目）时的默认行为 |

### 1.2 流程 A：只需邮箱验证码（默认）

```bash
# ① 发送验证码（仅允许 QQ 邮箱）
curl -X POST http://localhost:8081/api/auth/email-code \
  -H "Content-Type: application/json" \
  -d '{"email":"10001@qq.com"}'

# ② 从邮箱拿到 6 位码后注册
curl -X POST http://localhost:8081/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{"email":"10001@qq.com","emailCode":"123456","password":"Sh@2026abc"}'
```

**本地联调不想配 QQ 邮箱授权码？** 把配置改成：

```yaml
app:
  register:
    mail-enabled: false      # 验证码只写到服务端日志（WARN 级别）
```

然后从后端日志里搜 `【开发模式】验证码未真实发送`。⚠️ `prod` profile 下关闭该开关会**启动失败**，
这是防止误把调试开关带进生产的硬护栏。

### 1.3 流程 B：需要图片验证码

```bash
# ① 取一道题
curl http://localhost:8081/api/auth/captcha
# -> data: { captchaId, type, imageUrl, width, height, prompts }
#    type: 1 字符输入 / 2 单选 / 3 点选
#    imageUrl 是 5 分钟有效的 OSS 签名地址，答案绝不下发

# ② 提交答案（type=3 时用 clicks，坐标是原图像素）
curl -X POST http://localhost:8081/api/auth/captcha/verify \
  -H "Content-Type: application/json" \
  -d '{"captchaId":"<上一步的 captchaId>","answer":"K7P2"}'
# -> data: { captchaPassToken }   5 分钟有效
#    注册场景的凭证是**一次性**的：每发一次邮件码都要重新过一遍验证

# ③ 带 passToken 发邮件码（服务端会一次性消费它）
curl -X POST http://localhost:8081/api/auth/email-code \
  -H "Content-Type: application/json" \
  -d '{"email":"10001@qq.com","captchaPassToken":"<上一步的 token>"}'
# 没带或凭证无效 -> 40105 请先完成人机验证（前端应弹窗后重试）

# ④ 注册（注意：注册请求体里不再需要 captchaPassToken）
curl -X POST http://localhost:8081/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{"email":"10001@qq.com","emailCode":"123456","password":"Sh@2026abc"}'
```

**注册规则**

- 密码强度：8~32 位，必须同时含字母与数字，不能含空格，不能与学号相同；
- 登录名默认取 QQ 号（邮箱 @ 前部分），冲突时自动加序号；也可在注册时用 `username` 指定；
- **`username` 的字符集限制：只能是数字或大小写字母**（`^[0-9A-Za-z]+$`），最长 20 个字符。
  ⚠️ **不合法会直接返回 `40000` 报错，服务端不会静默改写** ——
  早期实现是 `replaceAll` 把非法字符抹掉，结果填「张三」会被抹成空串、再退化成 `u12345`，
  用户以为注册成功却永远登不上（找不到自己的账号），必须避免。
  下划线 `_`、连字符 `-`、空格、汉字、全角字符都算不合法。
  留空则由服务端按邮箱自动生成（QQ 邮箱即纯数字，天然合法）；
- 新用户 `role=0`（学生），默认配额 2GB（`app.quota.default-bytes`）；
- 邮箱验证码 10 分钟有效、一次性；同一邮箱 60 秒 1 封、1 小时 5 封；内网来源不做 IP 维度计数
  （否则机房全班共用一个出口 IP 会被整体限流）。

## 2. 登录与改密

```bash
# 登录：学生直接填学号
# 后台题库启用后需要先过人机验证（先看 GET /auth/human-check 的 login 字段）
curl -X POST http://localhost:8081/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"login":"20260001","password":"Sh@2026"}'

# 需要人机验证时带 captchaPassToken（见 §0.8）
curl -X POST http://localhost:8081/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"login":"20260001","password":"Sh@2026","captchaPassToken":"<凭证>"}'
# 没带或凭证无效 -> 40105 请先完成人机验证
# 凭证**不消费**：密码输错重试时 5 分钟内可以继续用同一个，不必重做验证码
```

```json
{
  "code": 0, "message": "ok",
  "data": {
    "token": "b7f3c2e1-....", "tokenName": "Authorization",
    "userId": 1001, "username": "20260001", "realName": "张三", "role": 0,
    "mustChangePassword": true
  }
}
```

- `mustChangePassword=true` 时必须先改密，否则其它接口返回 **40119**；
- 会话策略：4 小时过期、30 分钟无操作失效（`sa-token` 配置）；
- 登录失败连错 5 次锁定 10 分钟；账号不存在与密码错误返回**同一个** 40116，避免账号枚举。

```bash
# 改密（首登强制改密也走这个接口）
curl -X POST http://localhost:8081/api/auth/password \
  -H "Authorization: <token>" -H "Content-Type: application/json" \
  -d '{"oldPassword":"Sh@2026","newPassword":"MyPass123","confirmPassword":"MyPass123"}'

# 退出
curl -X POST http://localhost:8081/api/auth/logout -H "Authorization: <token>"
```

> 改密会踢掉**其它**终端的会话，但保留当前会话（否则首登改密的学生会被立刻弹回登录页）。

**校验规则**

| 字段 | 规则 |
|------|------|
| `nickname` | 去首尾空格；不能为空；最多 50 个字符（按字符数，中文算 1 个）；`null` 表示不改 |
| `avatar` | ❌ **不接受**：传了会返回 40000 并提示改用头像上传接口 |
| `signature` | 最多 255 个字符；去首尾空格；`null`/空串清空 |
| `gender` | `0` 未知 / `1` 男 / `2` 女；其它值报 40000；`null` 清空为 0 |
| `birthday` | `yyyy-MM-dd`；不能晚于今天；年份不早于 1900；`null` 清空 |

### 3.3 自定义头像（本次新增）

需求：**仅 JPG / PNG**、**≤ 5MB**、存阿里云 OSS；**换头像时服务端自动删除 OSS 上的旧头像**。

#### 上传 / 更换

```bash
curl -X POST http://localhost:8081/api/user/avatar \
  -H "Authorization: <token>" \
  -F "file=@my-face.png"
# -> 返回最新的完整资料（含 avatarKey / avatarUrl / avatarVersion）
```

```json
{
  "code": 0, "message": "ok",
  "data": {
    "userId": 1001, "username": "20260001", "nickname": "小明",
    "avatarKey": "avatar/1001/9b2f7c1a4e6d4f8a9023bcde5678ff01.png",
    "avatarUrl": "https://bucket.oss-cn-beijing.aliyuncs.com/avatar/1001/9b2f...png?Expires=...",
    "avatarVersion": "9b2f7c1a4e6d4f8a9023bcde5678ff01"
  }
}
```

#### 读取头像

| 方式 | 地址 | 说明 |
|------|------|------|
| **签名地址** | 资料接口返回的 `avatarUrl` | 1 小时有效。私有 Bucket 必须签名，而且 `<img src>` 无法携带 Authorization 头，所以**浏览器里就用这个** |
| **稳定地址** | `GET /api/user/avatar/{userId}` | 需要 `Authorization` 头，不会过期。适合能自行设置请求头的客户端（服务端渲染、管理后台、App） |

```bash
# 稳定地址读取（会带上 Cache-Control: private, max-age=3600）
curl -H "Authorization: <token>" -o avatar.png \
  "http://localhost:8081/api/user/avatar/1001"
```

#### 清除头像

```bash
curl -X DELETE http://localhost:8081/api/user/avatar -H "Authorization: <token>"
# -> 资料中 avatarKey / avatarUrl / avatarVersion 都变为 null，OSS 对象同时删除
```

#### 校验与行为（重点）

| 项 | 规则 |
|----|------|
| 格式 | 只认 **JPEG / PNG**。判定方式是 **magic bytes + ImageIO 真正解析**，不看文件名后缀、也不看 Content-Type —— 把文本改名成 `.png` 会被拒（40000） |
| 大小 | ≤ **5MB**，超出返回 **40082** |
| 尺寸 | 边长 ≤ 4096 像素；**只读元数据不解码像素**，避免 5MB 的"解压炸弹"打挂服务 |
| 新旧对象 | 每次生成新的 UUID Key；顺序为「先传新对象 → 再更新数据库 → 最后删旧对象」，任何一步失败都不会让数据库指向已删除的对象 |
| 换个头像后旧图还在？ | 删除失败时会留下一个无引用对象，由 **OSS 对账任务**（§7 的运维接口）在宽限期后回收 |
| 配额 | 头像**不计入**用户存储配额（每人只留一张，最大 5MB） |
| **修改频率** | **每 24 小时只能改一次**（更换与清除共用这个间隔），冷却中返回 **40123**，`message` 里带"约 X 小时后可再次修改" |

#### 24 小时冷却（本次新增）

防的是"恶意用户拿头像当免费图床反复刷图"：每换一次都会往 OSS 写一个新对象、删一个旧对象，
无限次刷会持续消耗存储与请求额度，也会把对账任务要扫的对象量推高。

| 字段 | 说明 |
|------|------|
| `avatarChangeableAt` | 资料接口（`GET /user/profile`、`POST /user/avatar`、`DELETE /user/avatar` 的返回体）里的**下次可修改时间**；为 `null` 表示现在就能改 |

```bash
curl -X POST http://localhost:8081/api/user/avatar \
  -H "Authorization: <token>" -F "file=@my-face.png"
# 冷却中 -> HTTP 200，业务码 40123
# { "code": 40123, "message": "头像每 24 小时只能修改一次，约 6 小时后可再次修改（2026-02-14 10:30 之后）", "data": null }
```

前端请据此**把按钮置灰并显示剩余时间**（本项目 `ProfileView.vue` 的写法可直接照搬），
不要等用户点了才报错 —— 但**真正的拦截在服务端**：清除头像（`DELETE /user/avatar`）走同一个冷却判定，
否则"换了立刻清掉再换"就把限制绕过去了。

#### 头像对象在 OSS 里的位置

```
avatar/{userId}/{uuid32}.{jpg|png}
```

该前缀**不对普通用户的 STS 开放**，只能由服务端写入；用户也无法遍历他人头像。

## 4. 上传文件

采用**服务端预签名 URL**：浏览器/客户端拿到的是签好名的 OSS 上传地址，
不需要持有任何 AK/SK，也不需要自己算签名。

```
① POST /oss/ticket            申请凭证：服务端确定 ObjectKey，签发一次性 uploadToken
                              （可能先要求人机验证，见 §0.8）
② POST /oss/put-url           小文件：拿单次 PUT 的预签名地址
   或 POST /oss/multipart/*   大文件：分片上传
③ POST /files/commit          建立索引（幂等）
```

> **人机验证只在第 ① 步**：后续 `put-url` / `multipart/*` 都要求由它签发的 `uploadToken`，
> 绕过 `ticket` 拿不到任何可用凭证，所以整条直传链路的闸门就是这一步。
> 旧的 `GET /oss/sts` 同样受约束（否则它就是个后门），需要时把凭证放查询参数。

### 4.1 小文件（≤ 一个分片）

```bash
# ① 申请凭证
curl -X POST http://localhost:8081/api/oss/ticket \
  -H "Authorization: <token>" -H "Content-Type: application/json" \
  -d '{"name":"作业.docx","size":2208391,"contentType":"application/vnd.openxmlformats-officedocument.wordprocessingml.document"}'
# -> { uploadToken, objectKey, partSize, partCount, expireSeconds, instantThresholdBytes, maxFileSizeBytes }
# 需要人机验证时先带 captchaPassToken（见 §0.8）：
#   -d '{"name":"作业.docx","size":2208391,"captchaPassToken":"<凭证>"}'
# 没带或无效 -> 40105 请先完成人机验证
# 通过一次后有 10 分钟免验证窗口（app.captcha.upload-pass-minutes），
# 整文件夹几十个文件只会打扰一次。

# ② 取预签名 PUT 地址
curl -X POST http://localhost:8081/api/oss/put-url \
  -H "Authorization: <token>" -H "Content-Type: application/json" \
  -d '{"uploadToken":"<token>","contentType":"application/octet-stream"}'
# -> { url, objectKey, contentType, expireSeconds }

# ③ 直传 OSS（注意 Content-Type 必须与上一步返回的一致！）
curl -X PUT "<上一步的 url>" -H "Content-Type: application/octet-stream" \
  --data-binary "@作业.docx"

# ④ 建立索引
curl -X POST http://localhost:8081/api/files/commit \
  -H "Authorization: <token>" -H "Content-Type: application/json" \
  -d '{"uploadToken":"<token>","parentId":0,"name":"作业.docx","contentType":"application/octet-stream","md5":"<可选，用于秒传>"}'
# -> { fileId, name, size, receipt, commitTime, renamed, duplicated, hit }
```

> ⚠️ **最容易踩的坑**：OSS V1 签名把 `Content-Type` 计入待签字符串。
> 预签名 URL 是用**某个** Content-Type 签的，请求头必须**原样发送**，
> 否则 OSS 返回 `SignatureDoesNotMatch`。所以 `/oss/put-url` 与
> `/oss/multipart/part-urls` 的响应里都会明确返回 `contentType`，照抄即可。

### 4.2 大文件（分片）

```bash
# ① 申请凭证（同 4.1）
# ② 初始化分片上传
curl -X POST http://localhost:8081/api/oss/multipart/init \
  -H "Authorization: <token>" -H "Content-Type: application/json" \
  -d '{"uploadToken":"<token>","contentType":"application/octet-stream"}'
# -> { uploadId }

# ③ 批量取分片地址（单次最多 500 个）
curl -X POST http://localhost:8081/api/oss/multipart/part-urls \
  -H "Authorization: <token>" -H "Content-Type: application/json" \
  -d '{"uploadToken":"<token>","uploadId":"<id>","partNumbers":[1,2,3]}'
# -> { contentType, urls:[{partNumber,url}] }

# ④ 每个分片 PUT 到自己的 url，Content-Type 用返回的 contentType；
#    从响应头 ETag 取值（去掉双引号）记下来

# ⑤ 完成分片上传（parts 按 partNumber 升序）
curl -X POST http://localhost:8081/api/oss/multipart/complete \
  -H "Authorization: <token>" -H "Content-Type: application/json" \
  -d '{"uploadToken":"<token>","uploadId":"<id>","parts":[{"partNumber":1,"etag":"..."},{"partNumber":2,"etag":"..."}]}'

# ⑥ 建立索引（同 4.1 第 ④ 步）

# 放弃上传（清理未完成分片，避免 OSS 持续计费）
curl -X POST http://localhost:8081/api/oss/multipart/abort \
  -H "Authorization: <token>" -H "Content-Type: application/json" \
  -d '{"uploadToken":"<token>","uploadId":"<id>"}'

# 断点续传：查已上传的分片（刷新/换设备后据此跳过已完成分片）
curl "http://localhost:8081/api/oss/multipart/parts?uploadToken=<t>&uploadId=<id>" \
  -H "Authorization: <token>"
```

**参数**

| 项 | 说明 |
|----|------|
| 分片大小 | 服务端决定：<500MB 用 5MB，≥500MB 用 10MB；超大文件自动放大以保证分片数 ≤ 10000（OSS 硬限制） |
| 预签名 URL 有效期 | 2 小时 |
| `uploadToken` 有效期 | 2 小时（必须够传完一个大文件；中途失效会导致已传分片作废） |
| 单文件上限 | 2GB（`app.upload.max-file-size-bytes`） |
| 秒传 | 传 `md5` 且命中同用户已有文件时，服务端直接 CopyObject，`hit=true`；>200MB 建议只算首尾各 1MB + size + name 的抽样指纹 |

> **ObjectKey 完全由服务端签发**，客户端不要自己拼 key；
> `commit` 也不接受 `size`，服务端以 OSS `headObject` 的真实大小为准 ——
> 这两条是防止伪造回调与刷配额的关键。

## 5. 下载回本地（本次新增）

后端提供**两种**下载方式：

| 方式 | 接口 | 适用 |
|------|------|------|
| 签名 URL | `GET /files/{id}/download-url` | 客户端能直连 OSS 域名，把流量压力留在 OSS |
| **服务端流式下载** | `GET /files/{id}/download` | 客户端只连业务服务器；**支持 Range 断点续传** |

```bash
# 方式一：拿 10 分钟有效的签名地址，交给下载工具
curl "http://localhost:8081/api/files/123/download-url" -H "Authorization: <token>"
# -> { "url": "https://bucket.oss-cn-beijing.aliyuncs.com/homework/...?Expires=..." }
#    ⚠️ 用这个 URL 直接下载，勿再带 Authorization。
#    ⚠️ data 必须是**对象**（`{ url }`），不能是裸字符串 —— 曾经实现成裸字符串，
#       前端 `const { url } = await ...` 解构出 undefined，`<a href>` 把它转成字面量
#       "undefined" 并按相对路径打开 `https://站点/undefined`，用户只看到
#       "404 页面不存在"（其实是前端路由的 not-found 页），且控制台毫无报错。
#       契约守卫：FileUrlContractTest。

# 方式二：服务端转发（推荐用于后端自测 / 内网客户端）
curl -H "Authorization: <token>" -o 作业.docx \
  "http://localhost:8081/api/files/123/download"

# 断点续传（curl 自动带 Range，服务端返回 206）
curl -H "Authorization: <token>" -C - -o 作业.docx \
  "http://localhost:8081/api/files/123/download"

# 手工指定区间
curl -H "Authorization: <token>" -H "Range: bytes=0-1023" \
  "http://localhost:8081/api/files/123/download" -o part.bin
```

**实现要点**

- 返回 `Content-Disposition` 时同时给 ASCII 回退名与 RFC 5987 的 `filename*=UTF-8''...`，
  中文文件名在浏览器里不会乱码、也不会丢扩展名；
- 支持单段 Range（`bytes=a-b`、`bytes=a-`、`bytes=-n`）：命中返回 **206** 并带 `Content-Range`，
  未命中/畸形 Range 退回 **200** 完整内容（宁可多传一次，也不让下载失败）；
- 响应头带 `Accept-Ranges: bytes`，下载管理器才会尝试续传；
- 越权与"文件不存在"统一返回 40070，不泄露文件是否存在；
- 预览用 `GET /files/{id}/preview-url`，只允许**可安全内联**的类型（图片 / 视频 / 音频 /
  文本 / Office 正文提取）；**PDF 已按需求排除**，`html`/`svg` 永远不允许内联（避免 XSS）。

> ⚠️ 服务端流式下载的流量经过业务服务器。批量分发大文件时请用签名 URL 方式，
> 否则机房出口带宽会打满业务服务器。

### 6.1 在线阅览

#### 图片 / 视频 / 音频 → 流式预览（支持 Range）

> **PDF 不在预览之列**（需求方要求）：`viewType` 仍是 `pdf`、列表里仍有 PDF 图标，
> 但 `previewable=false`、`preview-url` 返回 `40073`，前端**点击整行不弹窗、下拉框里不出现"在线预览"**，
> 只保留下载。判断依据请用 `previewable`，不要用 `viewType !== 'none'`。

```bash
# ① 拿签名地址（推荐：可直接给 <img src> / <video src>，无需请求头）
curl "http://localhost:8081/api/files/123/preview-url" -H "Authorization: <token>"
# -> { "url": "https://bucket.oss...?Expires=..." }   10 分钟有效
#    同样是**对象**（与 download-url 一致），理由见 §6 方式一的说明

# ② 服务端流式预览（需要带 Authorization；二进制响应，不是 JSON）
curl -H "Authorization: <token>" -o out.png "http://localhost:8081/api/files/123/preview"

# ③ 视频/音频拖动进度条：浏览器会自动带 Range，也可以手工指定
curl -H "Authorization: <token>" -H "Range: bytes=0-1023" \
  "http://localhost:8081/api/files/123/preview" -o part.bin
```

行为：

- 响应头 `Content-Disposition: inline`，浏览器直接渲染而不是弹下载框；
- 支持 `Range` 时返回 **206** + `Content-Range`（视频/音频靠它跳转进度条）；
- `Content-Type` 由服务端按后缀白名单映射，并带 `X-Content-Type-Options: nosniff`；
- 对 `text` / `office` / `none` 类型调用会返回 **40073**，并在 message 里告诉你该用哪个接口。

#### docx / pptx 内嵌图片 → data URL 列表

正文提取只能拿到**纯文字** —— 图片在 zip 里是独立条目（docx 为 `word/media/`，
pptx 为 `ppt/media/`），解析 XML 时会被一起剥掉。所以图文作业要另外调这个接口：

```bash
curl "http://localhost:8081/api/files/123/embedded-images" -H "Authorization: <token>"
```

```json
{
  "code": 0, "message": "ok",
  "data": {
    "images": [
      { "name": "image1.png", "contentType": "image/png", "size": 20480,
        "dataUrl": "data:image/png;base64,iVBORw0KGgo..." }
    ],
    "skipped": 2
  }
}
```

要点：

- 返回的是 **data URL**，前端可直接给 `<img src>`：既不需要签名地址，
  也**不会在 OSS 里多出对象**（预览是只读行为，不该产生垃圾对象）；
- `skipped` 是被跳过的张数，原因有三类：单张超过 **2MB**、累计超过 **8MB**、
  张数超过 **40**，以及**格式不是浏览器可渲染的位图** ——
  Word 常见的 `emf` / `wmf` 矢量图，以及 `svg`（与 `FileViewType.UNSAFE_IMAGE`
  口径一致，属于不安全类型）都会被跳过。前端应提示"另有 N 张未显示"；
- 收哪些后缀**复用 `FileViewType` 的位图白名单**（jpg/jpeg/png/gif/webp/bmp），
  `Content-Type` 也走同一份白名单映射，不回显文档里声明的类型；
- 非 Office 文件、以及没有图片的文档，返回 `images: []`（**不是错误**），
  所以前端对任意类型调用都不会炸；
- 与 `/text` 一样受 **20MB** 上限与解压炸弹防护约束。

#### 文本 / Office 正文 → JSON 文本

```bash
curl "http://localhost:8081/api/files/123/text" -H "Authorization: <token>"
```

```json
{
  "code": 0, "message": "ok",
  "data": {
    "id": 123, "name": "读书笔记.txt", "suffix": "txt", "viewType": "text",
    "size": 20480, "charset": "GBK",
    "content": "第一行\n第二行\n…",
    "truncated": false, "maxChars": 200000, "hint": null,
    "html": null
  }
}
```

要点：

- **自动处理编码**：UTF-8 BOM 与 GBK 都能正确解码，并在 `charset` 里告诉你实际用了哪种
  （学生用中文 Windows 记事本存的文件就是 GBK，不处理会整篇乱码）；
- `html` 只有 `docx` / `xlsx` 才有值：**服务端渲染的结构化 HTML**（段落、标题、加粗斜体、
  表格），前端扔进 `v-html` 就是"原格式"视图，比纯文本强得多；其它格式或渲染失败时为 `null`，
  回退到纯文本视图即可。它**不是像素级还原**（字体、分页、浮动图片都不还原）——
  要完整版面仍然要下载原文件；
  - 渲染上限：正文 HTML ≤ 40 万字符、表格 ≤ 300 行 × 40 列，超出的部分会被截断；
  - 文档里的文本**全部转义**，标签只按白名单生成；前端仍建议再用一层白名单过滤
    （本项目是 `sanitizeOfficeHtml()`），双保险；
- `docx` / `pptx` / `xlsx` 会提取**纯文本**，`hint` 固定为"已提取纯文本，排版与表格会丢失；
  需要完整版面请下载原文件"（`docx` / `xlsx` 另有 `html` 可看近似版面，但 `hint` 不变 ——
  别用 `hint` 是否为空来判断有没有 HTML，要看 `html` 字段本身）；
- **图片会被剥掉**：`docx` 的图在 `word/media/`、`pptx` 在 `ppt/media/`，是 zip 里的独立条目，
  解析 XML 时不会进入正文。图文作业请再调 `GET /files/{id}/embedded-images` 拿图；
- `doc`（Word 97-2003）同样走这个接口：服务端按 OLE2 容器 + FIB/piece table 提取正文。
  它是**不压缩**的老格式，提取质量受格式本身限制：
  - 加密（"密码保护"）的 `.doc` 返回 `40073`，前端应提示下载后用 Word 打开；
  - 表格只保留单元格文字（单元格标记当换行），页眉页脚/批注/文本框属于正文之外的"故事"，
    不会被当作正文输出（只取 `ccpText` 范围）；
  - 域代码（如 `HYPERLINK`）会被丢弃，**域结果保留** —— 所以目录、页码这类"看得见的字"还在；
  - 图片、公式对象、图形无法提取（`.doc` 的图片不参与内嵌图片接口），
    只会留下一句"没有可提取的文字"的提示（若全篇如此）。
  旧版 `.ppt` / `.xls`（二进制）目前没有可靠的无依赖解析方案，仍为 `viewType=none`，只能下载；
- 大小上限：文本 **5MB**、Office **20MB**；返回字符上限 `maxChars` = 20 万，超出时 `truncated=true`；
- 超限返回 `40082`，前端应提示"文件过大，请下载后查看"。

### 6.2 图片管理（相册）

跨目录把本人网盘里所有**可在线预览的图片**摊平列出，按上传时间倒序：

```bash
curl "http://localhost:8081/api/images?page=1&size=60" -H "Authorization: <token>"
```

```json
{
  "code": 0, "message": "ok",
  "data": {
    "page": 1, "size": 60, "total": 37,
    "records": [
      {
        "id": 501, "name": "实验照片.png", "suffix": "png", "size": 880123,
        "parentId": 12, "viewType": "image",
        "previewUrl": "https://bucket.oss...?Expires=...",
        "previewApiUrl": "/api/files/501/preview",
        "createTime": "2026-09-11 10:20:30", "updateTime": "2026-09-11 10:20:30"
      }
    ]
  }
}
```

要点：

- 只收**可安全内联的位图**：jpg / jpeg / png / gif / webp / bmp；**不含 svg / ico**；
- 每项已带 `previewUrl`（1 小时签名地址），铺网格时**不用为每张图再发一次请求**；
- `parentId` 用来做"跳转到所在文件夹"；
- 与 `GET /files?category=image` 的区别：那个只筛**当前目录**，这个摊平**整个网盘**。

**行为约定**

- 删除文件夹时整棵子树一起进回收站；还原时如果原父目录还在回收站里，会**一并还原**（否则还原出来的东西看不见）；
- 还原时若原名已被占用，自动加 `(1)` 并正常返回，不会抛唯一键冲突；
- 彻底删除先删数据库（事务内），OSS 对象在**事务提交后**异步删除；
  失败的对象成为孤儿，由每日对账任务回收；
- 目录层级上限 20 层，服务端强制校验（新建与移动都会校验）。

| 键 | 说明 |

## 8. 公告（本次新增）

超管发布/撤回公告，公告带**注意力分级**；数据落库表 `announcement`。

### 8.1 数据模型

| 字段 | 说明 |
|------|------|
| `level` | **注意力分级**：`1` 普通 / `2` 重要 / `3` 紧急 |
| `status` | `0` 草稿 / `1` 已发布 / `2` 已撤回 |
| `publish_time` | 发布时间；为空按"发布即可见"处理 |
| `expire_time` | 过期时间；**为空表示不过期**（一直生效到手动撤回） |
| `created_by` | 发布人（超管）user_id，便于追溯 |

一条公告**此刻是否对用户可见**，判定条件是三者同时成立：

```
status = 1  且  (publish_time is null or publish_time <= now)  且  (expire_time is null or expire_time > now)
```

后台列表每项都带一个 `effective` 字段，就是上面这个判定的结果 ——
**"发布了但其实没生效"必须让管理员看得见**，否则会出现"我明明发了，用户说没看到"这种扯皮。

### 8.2 用户端读取（任何已登录用户）

```bash
curl "http://localhost:8081/api/announcements/active" -H "Authorization: $TOKEN"
# -> data: [ { id, title, content, level, publishTime, expireTime } ]
```

- 只返回**当前生效**的公告；草稿与已撤回对用户不存在；
- 排序：**分级降序 → 发布时间降序 → id 降序**（紧急永远在最前，同级新的在前）；
- 单次最多 20 条：公告是"打扰"不是信息流，一次给太多反而没人看；
- 响应里**不含** `status` / `createdBy`：用户端不需要，少下发一个字段就少一个信息泄露面；
- `content` 是**纯文本**（后端拒绝 HTML，前端按换行渲染即可），`\n` 会原样保留。

前端按 `level` 决定打扰方式（本项目 `AnnouncementCenter.vue` 的实现）：

| level | 展示 | 能否关闭 |
|:--:|------|:--:|
| 1 普通 | 顶部横幅（品牌色） | ✅ 可关 |
| 2 重要 | 顶部横幅（警示色） | ✅ 可关 |
| 3 紧急 | **强制弹窗**，只有「我已知晓」一个出口 | ❌ 不可关（不能用 Esc / 点遮罩绕过） |

> "已读"是纯客户端概念（本项目存在 `sessionStorage`）：公告是广播，不是消息队列，
> 为它维护一份 per-user 已读表不值得。用 `sessionStorage` 而不是 `localStorage`，
> 是因为机房是**公用电脑** —— 上一位同学关掉的公告，下一位登录时应该重新看到。

### 8.3 后台管理（**仅超级管理员**）

公告会影响全站每一个人（紧急公告还会强制弹窗打断操作），所以这个权限不下放给普通管理员或教师。

| 方法与路径 | 说明 |
|------|------|
| `GET /admin/announcements` | 列表。查询参数：`keyword`（标题/正文模糊）、`status`、`level`、`page`、`size`（默认 20，上限 100） |
| `GET /admin/announcements/{id}` | 详情 |
| `POST /admin/announcements` | 新建。**落为草稿**，需再调 `publish` 才对用户可见 |
| `PUT /admin/announcements/{id}` | 修改。⚠️ **仅草稿 / 已撤回可改** |
| `PUT /admin/announcements/{id}/publish` | 发布：草稿 / 已撤回 → 已发布，`publishTime` 取当下 |
| `PUT /admin/announcements/{id}/recall` | 撤回：已发布 → 已撤回（**只改状态、保留 `publishTime`**，便于追溯） |
| `DELETE /admin/announcements/{id}` | 删除（物理删除）。⚠️ 仅草稿 / 已撤回可删 |

请求体（新建/修改）：

```json
{ "title": "今晚 22:00-23:00 机房断电维护", "content": "请提前保存作业。\n维护期间无法上传下载。", "level": 3, "expireTime": "2026-02-15T08:00:00" }
```

| 字段 | 规则 |
|------|------|
| `title` | 必填，≤ 120 字 |
| `content` | 必填（纯文本），≤ 5000 字 |
| `level` | 不传默认 `1`；只接受 1/2/3，其它值返回 `40000`（不允许"静默降级成普通"） |
| `expireTime` | 可为空（不过期）；填了必须是**将来**且 ≤ 365 天后 |

**状态机**（刻意做得"啰嗦"，只有这四条边）：

```
新建 ──▶ 草稿 ──publish──▶ 已发布 ──recall──▶ 已撤回 ──publish──▶ 已发布
            │                  │                │
            └──── delete ──────┘                └── delete ──┘
```

两条关键约束：

1. **已发布的公告不能直接改/删，必须先 `recall`**（返回 `40095`，提示"请先撤回再修改"）。
   公告是有时间含义的（"今晚 22:00 断网"），静默改掉内容等于篡改历史 ——
   用户可能会拿它当依据做判断；
2. **撤回只改状态、不删数据**，且保留 `publishTime`，事后能查清"谁在什么时候发过什么"。

```bash
# 新建（得到 id）
curl -X POST "http://localhost:8081/api/admin/announcements" -H "Authorization: $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"title":"机房维护","content":"今晚 22:00-23:00 断网","level":2,"expireTime":"2026-02-15T08:00:00"}'
# 发布 / 撤回 / 删除
curl -X PUT "http://localhost:8081/api/admin/announcements/1/publish" -H "Authorization: $TOKEN"
curl -X PUT "http://localhost:8081/api/admin/announcements/1/recall"  -H "Authorization: $TOKEN"
curl -X DELETE "http://localhost:8081/api/admin/announcements/1" -H "Authorization: $TOKEN"
# 列表（筛已发布的紧急公告）
curl "http://localhost:8081/api/admin/announcements?status=1&level=3&page=1&size=20" -H "Authorization: $TOKEN"
# -> records: [{ id, title, content, level, status, publishTime, expireTime,
#                createdBy, createTime, updateTime, effective }]
```

所有写操作都会落审计日志（`ANNOUNCEMENT_CREATE` / `_UPDATE` / `_PUBLISH` / `_RECALL` / `_DELETE`）。

## 9. 自动验收

```powershell
# 需要后端已启动，且 MySQL / Redis / OSS 可用
cd <项目根>
pwsh ./scripts/api-smoke.ps1 -Login admin -Password 'YourInitPassword'
```

脚本会跑：公开配置 → 登录 → 读取/部分更新个性属性 → 非法值被拒 → 容量 →
申请凭证 → 直传 OSS → commit → 幂等 → 列表 → **下载回本地并逐字节比对 MD5** →
Range(206) → 中文文件名 `filename*` → 无效 token 被拒 → 回收站删除/还原/彻底删除。

它会自动生成一个**中文名**的临时文件，所以顺带验证了中文文件名的下载编码。

> ⚠️ **题库启用后登录与上传都要人机验证**，脚本会返回 40105 并给出提示。
> 两种处理方式（见 §0.8）：
> ```powershell
> # A. 传一个凭证（浏览器过一次验证码，从 /auth/captcha/verify 响应里取）
> pwsh ./scripts/api-smoke.ps1 -Login admin -Password 'xxx' -CaptchaPassToken 5f3c...
> # B. 临时关闭人机验证（在服务器 env 里设 CAPTCHA_ENABLED=false 并重启；跑完改回 true）
> ```

## 10. 排查清单

| 现象 | 常见原因 |
|------|----------|
| 启动即失败：`未配置 app.admin.init-password` | 环境变量没设置；超管初始化不允许空密码 |
| 启动即失败：`生产环境禁止关闭 app.register.mail-enabled` | prod profile 下把邮件通道关了，属于硬护栏 |
| 注册返回 40122 | `app.register.enabled=false` |
| 注册返回 50020 且日志提示未配置发件邮箱 | 缺 `MAIL_USERNAME` / `MAIL_AUTH_CODE`（是 QQ 邮箱**授权码**，不是登录密码） |
| 登录/上传返回 **40105** | 后台题库已启用，请求没带 `captchaPassToken`。前端应先弹验证码窗口（§0.8）；命令行用 `api-smoke.ps1 -CaptchaPassToken`，或临时 `CAPTCHA_ENABLED=false` |
| 用户抱怨"每次上传都要做验证码" | 免验证窗口被关小了：`app.captcha.upload-pass-minutes`（默认 10） |
| 题库已清空但登录仍被要求验证码 | 题库状态有最长 60 秒缓存（`app.captcha.id-cache-seconds`）；后台增删改题目会立即清除，手工改库不会。等 1 分钟或 `redis-cli DEL cap:enabled` |
| 验证码区显示「验证码加载失败」 | 弹窗里的**具体原因**才是关键：① 题库为空 → 让管理员上传题目；② 出现「请求方法不支持」→ 前端把 `GET /auth/captcha` 误当 POST 调（历史缺陷：这种情况后端曾错回 500，现已改为 405，见 `GlobalExceptionHandlerTest`）；③ 其它 → 多为网络/网关问题 |
| 验证码图片是裂图（有文字但图不显示） | 图片是 OSS 签名地址：检查 `aliyun.oss.*` 配置与 Bucket ACL；签名地址过期（5 分钟）后点「换一题」即可 |
| 注册返回 40104 | 题库为空却仍在要求人机验证 —— 正常情况下会自动降级不要求；若出现说明 `app.captcha.enabled` 与实际题库状态不一致，先上传题目 |
| 所有受保护接口 40100 | 请求头没带 `Authorization`，或 token 过期（4 小时 / 30 分钟空闲） |
| 后台接口一律 403 | 角色不足；或漏了 `StpInterfaceImpl`（缺它 `checkRole` 永远取不到角色） |
| PUT OSS 报 `SignatureDoesNotMatch` | 请求的 `Content-Type` 与预签名时不一致，用响应里返回的 `contentType` |
| commit 返回 40050 | 直传没成功、或 bucket/endpoint 配错 |
| commit 返回 40061 | `uploadToken` 过期（默认 2 小时）或已被消费 |
| 下载文件名乱码 | 客户端没解析 `filename*`（RFC 5987），服务端已同时给 ASCII 回退名 |
| 回收站清空后容量没变 | 容量是缓存值；`POST /admin/ops/reconcile-storage` 可重算 |
| 公告发布了但用户看不到 | 看后台列表的 `effective`：还是草稿 / `expireTime` 已过 / `publishTime` 在未来 |
| 改公告返回 40095 | 公告处于已发布状态，必须先 `recall` 撤回再改 |
| 公告接口一律 403 | 公告管理仅超管（`role=9`） |
| 换头像返回 40123 | 24 小时冷却未到；同时确认已跑 `migration_v2.2.sql`（缺列会是 SQL 错误而不是 40123） |
